01 Architecture & pipeline. +
End-to-end pipeline · runs unattended every 30 minutes
Fetch

OAuth2 against Azure AD → OData v4 calls to Dataverse. Incremental sync — only fetches leads created or modified since the last successful run; state persisted in last_run_timestamp.txt.

Filter

Drops closed leads (Won / Lost / Junk) and leads already scored — strict score-once policy.

Preprocess

Case-fold + rare-category collapse (n < 30 → "Other"); temporal features from timestamps; description-text mining for size (kW), timeline, and sentiment; missingness flags as features; log1p + 99th-percentile clip on numerics; PIN-prefix geographic features.

Encode

sklearn ColumnTransformer — OrdinalEncoder for low-cardinality, smoothed TargetEncoder for high-cardinality, passthrough for numerics. 32 transformed features.

Score

XGBoost classifier (n_estimators=500, max_depth=6) → probability → 0–100 score.

Tier & rules

Hot (≥70) / Warm (≥40) / Cold (<40). Then business rules: Order size ≥ 50 kW → force Hot (with recorded reason).

Write back

PATCH the lead in Dataverse with ispl_aiscore, ispl_aitier, probability, scored timestamp, and rule-trigger reason — so reps see why a lead is Hot.

Operate

Windows Task Scheduler triggers run_sync.bat every 30 min. Safety rails: MAX_LEADS_PER_RUN = 5000, score-once, daily rotating logs.

02 Model & features. +
Training

32,701 leads from Jun 2025 – Jan 2026 (17.3% win rate). Out-of-time tested on 10,310 leads from Feb–Apr 2026 (16.95% win rate). Out-of-time validation, not random split — mirrors how the model is actually used.

Performance

ROC-AUC 0.808 · PR-AUC 0.6745 · Top-decile capture 47.9% — the top-scored 10% of leads contain almost half of all eventual wins.

Features (32)

9 low-card categoricals (Lead Source, Product Category, Industry, Zone, etc.) → OrdinalEncoder. 3 high-card categoricals (Campaign Name, State, PIN prefix) → smoothed TargetEncoder. 11 numeric (log1p(Order Size), temporal, description metrics). 9 binary (keyword + missingness flags).

Interpretability

SHAP wired in for training-time explainability; rule-trigger reason field surfaces the "why" inside the CRM.

04 Key engineering decisions. +
Batch sync into CRM, not a separate dashboard.
Sales reps live in Dynamics — pushing scores into their existing tool drove adoption far better than building a parallel UI.
Business rules as a layer on top of ML.
Pure model scores under-call rare large orders. The 50 kW override captures domain knowledge the model can't learn statistically from few examples.
Score-once policy.
Locks in the score at lead intake instead of re-scoring on every edit — prevents noise from reps updating descriptions.
Rule-trigger reason field.
Telling reps why a lead is Hot ("order size 80 kW") turned a black-box score into something they trust and act on.
Disabled the timeline rule after testing.
EDA showed templated "how soon" answers correlated with cold leads, not hot. Built the rule, validated it, disabled it — instead of trusting intuition.
Out-of-time validation, not random split.
Tested on Feb–Apr 2026 data after training on Jun 2025 – Jan 2026 — mirrors how the model is actually used in production.

01 Architecture & retrieval pipeline. +
Two paths through one shared Qdrant store · ingest + query
Ingest

Drop a PDF in input/ or POST to FastAPI → GROBID parses to TEI XML → custom parser cleans, forward-fills section context, marks terminal sections (References, Acks) → tiktoken chunker (cl100k_base, 800-token chunks, section-respecting) → BGE-large embeddings → Qdrant Cloud.

Retrieve

4-stage hybrid — vector search (top 20) + BM25 keyword search (top 20) → Reciprocal Rank Fusion (scale-invariant) → cross-encoder rerank (ms-marco-MiniLM-L-6-v2) → top 5 to LLM. Terminal chunks always filtered.

Generate

3 task modes: Q&A (within one paper), Compare (across N papers in parallel), Summarise (section-by-section or whole). Gemini 2.5 Flash default · Flash Lite for simple queries · Mistral 7B (HF) fallback · multi-key rotation.

Operate

watchdog auto-ingests input/. FastAPI exposes /ingest, /qa, /compare, /summarize. 24h query cache; per-call usage log to llm_usage.jsonl. Streamlit primary UI; Waaree-branded React SPA in development.

03 Key engineering decisions. +
GROBID as a service, not a library.
Wrapping a mature Java parser in Python would re-implement years of work badly. Running it as a Docker service keeps the pipeline lightweight and lets GROBID upgrade independently.
Hybrid retrieval — all four stages earn their place.
Vector alone misses exact terms ("ORR", "Pt/C 20%"); BM25 alone misses paraphrases; RRF merges them without normalising scores; cross-encoder rerank gives final precision on the top 10.
RRF instead of weighted score fusion.
Score normalisation between vector cosine and BM25 is a footgun. RRF only uses ranks, so it's scale-invariant and parameter-free.
Two Qdrant collections.
chunks for retrieval, doc_records for paper-level operations (listing, similar-paper lookup). Payload indexes on doc_id / main_section / is_terminal turn filtered queries from full-scans into O(log n).
Multi-key Gemini rotation + Mistral fallback.
Free-tier rate limits would otherwise kill the system during heavy ingestion. Rotation + fallback + 24h cache keeps it usable end-to-end.
Terminal-section filtering at parse time.
References / Acknowledgements chunks are marked at parse time and excluded from retrieval — so the LLM can never accidentally cite a bibliography line as evidence.
Token-aware chunking with tiktoken.
Exact cl100k_base token counts prevent silent overflows into Gemini; chunks respect section boundaries so context never bleeds across topics.
Per-call usage log (llm_usage.jsonl).
Timestamp, model, key label, tokens, success/failure — you can't optimise what you can't see. Makes cost and key health visible.

01 Architecture & pipeline. +
Parallel scraping · hybrid Q&A router (instant lookup vs LLM)
Scrape

Selenium pulls high-resolution figure URLs (the D000xx hi-res URLs only load after Google Patents' JavaScript runs) → PyMuPDF renders the PDF at 300 DPI as fallback → BeautifulSoup extracts metadata, abstract, description, claims. Two-tier scraping guarantees 100% figure coverage.

Clean & store

text_cleaner.py normalises encoding artefacts and whitespace; storage.py writes a structured folder per patent (metadata.json, abstract.txt, description.txt, claims.txt, figures/). No database — zip the directory and the entire corpus moves.

Extract

Regex finds reference-number candidates in the Preferred Embodiment section → NLTK POS tagging filters out non-nouns and generic terms ("layer", "film", "substrate") → produces ref_number → component_name mapping. Low-confidence picks flagged with (?).

Annotate

Tesseract OCR locates reference numbers on each figure → Pillow draws component-name labels (semi-transparent white background, navy text) → saves annotated PNG alongside the original.

Answer

5-question Q&A with a hybrid router. Q1/Q3/Q4 (owner / dates / jurisdiction) answered instantly from metadata. Q2 (invention summary) and Q5 (step-by-step lab reproduction) generated by Gemini 2.5 — LLM used only where language quality matters.

Operate

Flask + Waitress (8 threads). Background scraping with threading.Lock prevents duplicate scrapes. Frontend polls /api/status. Every pipeline stage exposed as a REST endpoint so engineers can re-run a single stage without re-scraping.

03 Key engineering decisions. +
Two-tier figure scraping.
Selenium first — the hi-res D000xx URLs only load after Google Patents' JavaScript runs. PyMuPDF rendering at 300 DPI as a fallback guarantees 100% figure coverage even when scraping fails.
Hybrid Q&A router — LLM only where it earns its place.
Q1/Q3/Q4 are pure metadata lookups; spending a Gemini call on them would waste tokens and add latency. Q2 (summary) and Q5 (reproduction guide) are where language quality matters, so they go to Gemini.
NLTK POS filtering for component names.
Raw regex matches on reference numbers pick up generic words ("layer", "film", "substrate"). POS tagging filters down to genuine noun phrases; low-confidence picks are flagged with (?) so engineers can verify rather than trust blindly.
Filesystem-per-patent, no database.
Each patent gets its own folder with metadata.json, abstract.txt, description.txt, claims.txt, and figures/. Portable — zip the directory and the entire patent corpus moves with it. No schema migrations, no DB to host.
Every stage is independently callable.
Component extraction and figure annotation each have their own REST endpoint, so engineers can re-run a single stage without re-scraping. Helpful when tuning the OCR / NLTK steps on already-scraped patents.
Async background scraping with in-memory job locks.
Scraping is slow (Selenium + figure downloads). Kicked off as a background thread; frontend polls /api/status. A threading.Lock prevents the same patent from being scraped twice concurrently.
